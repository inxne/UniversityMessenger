# Онбординг команды и ИИ-ассистентов

Этот документ обязателен к прочтению каждым разработчиком и каждым ИИ-ассистентом, который подключается к проекту.

## Блок для ИИ-ассистента (скопировать и вставить в начале сессии)

ИНСТРУКЦИЯ ДЛЯ ИИ:
Ты ИИ-ассистент в команде из трёх разработчиков. Проект: University Messenger, корпоративный мессенджер с оконечным шифрованием. Стек: C#, .NET 10, ASP.NET Core, EF Core SQLite, SignalR, криптослой EndToEndCrypto.

ТВОЙ АЛГОРИТМ ПРИ СТАРТЕ СЕССИИ:
1. Прочитай или попроси меня дать содержимое файлов: docs/handoff.md, TASKS.md, docs/changelog.md, docs/team-onboarding.md.
2. Кратко перескажи текущий статус проекта и перечисли задачи со статусом СВОБОДНА из TASKS.md.
3. Дождись, пока я выберу задачу.
4. Предложи команды создания ветки и коммита-замка на доске.

ТВОИ ЖЁСТКИЕ ПРАВИЛА:
- Никаких коммитов в main. Работа только в ветках task/имя-задачи.
- Редактируй только файлы, указанные в описании задачи на доске TASKS.md. Нужен чужой файл — остановись и скажи мне.
- Коммиты на русском с префиксами feat, fix, docs, chore.
- После каждого логического шага предлагай строку в docs/changelog.md и, если есть новые нюансы, вопросы-ответы в docs/defense-notes.md.
- Перед коммитом напоминай выполнить dotnet build. Красную сборку не коммитим.
- Git-команды не выполняй скрытно: выдавай их мне блоками кода, выполняю я.

Подтверди правила и начни с шага 1.

## Порядок работы разработчика

1. Начало: git switch main, git pull, прочитать docs/handoff.md.
2. Взятие задачи: выбрать СВОБОДНУЮ в TASKS.md, создать ветку git switch -c task/pN-имя,
   перенести задачу в раздел В работе со своим именем, сделать коммит-замок и запушить:
   git add TASKS.md, git commit -m "chore: задача ПN взята в работу", git push -u origin task/pN-имя.
3. Работа: ИИ даёт код по задаче, вставляешь, dotnet build, коммит. Повторять до готовности.
4. Сдача: git switch main, git pull, git merge task/pN-имя, git push, git branch -d task/pN-имя.
5. Передача смены: в TASKS.md перенести задачу в Готово, переписать docs/handoff.md
   под новую реальность, финальный коммит документов и push.

## Красные линии

- Коммит напрямую в main: запрещён, main всегда стабилен.
- git push --force: запрещён, уничтожает чужую историю.
- Правка файлов вне своей задачи: запрещена, ведёт к конфликтам.
- Удаление messenger.db при запущенном сервере: ошибка, файл заблокирован.
- Пропуск обновления changelog и handoff: следующий человек теряет контекст.
