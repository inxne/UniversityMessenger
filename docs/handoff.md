# Передача состояния проекта

Этот файл обновляет ТОТ, КТО ПОСЛЕДНИМ РАБОТАЛ, в конце своей сессии.
Любой участник и любой ИИ начинает сессию с чтения этого файла.

## Текущий этап
П3 завершён. Следующий по плану П4: сервер принимает и отдаёт только шифротексты.

## Что готово кратко
- Core: модели с Message.Ciphertext и User.PublicKey, сервисы под шифротекст, криптослой EndToEndCrypto.
- Server: JWT, SQLite, SignalR, Swagger. ВАЖНО: сервер пока принимает открытый текст как шифротекст, контракт не менял. Это главная задача П4.
- Console: демо слепого сервера.
- Docs: architecture, changelog, defense-notes, setup-new-pc, handoff, ai-start-prompt.
- Team: доска TASKS.md, замки, ветки на задачу.

## Известные факты и грабли
- messenger.db пересоздан под новую схему. При новых изменениях схемы удалять снова при остановленном сервере.
- До П4 поле ciphertext в запросах временно содержит открытый текст: сервер контракт не менял. После П4 туда пойдёт только base64.
- MessageDto в сервере теперь с полем Ciphertext, тестовая страница index.html выводит m.ciphertext.
- Коммиты на русском с префиксами feat fix docs chore.
- После каждого шага строка в docs/changelog.md, новые вопросы защиты в docs/defense-notes.md.
- Swagger без кнопки Authorize: токен передаём заголовком вручную или через PowerShell.

## Ближайшие шаги П4
1. Взять задачу П4 замком на доске.
2. RegisterRequest получает поле PublicKey, сервер передаёт его в AuthService.Register и требует непустым.
3. SendMessageRequest переименовать в SendCiphertextRequest с полем Ciphertext, сервер больше не принимает открытый текст.
4. UserDto получает поле PublicKey, чтобы клиенты могли вывести общий секрет.
5. Проверка через PowerShell: регистрация с ключом, отправка base64, история возвращает base64.
6. Документы, закрытие задачи, коммит, push.
