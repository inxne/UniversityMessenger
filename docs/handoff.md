# Передача состояния проекта

Этот файл обновляет ТОТ, КТО ПОСЛЕДНИМ РАБОТАЛ, в конце своей сессии.
Любой участник и любой ИИ начинает сессию с чтения этого файла.

## Текущий этап
П5 завершён: вся криптография готова, включая группы. Остались П6 (клиент MAUI с вёрсткой) и П7 (развёртывание на локальном сервере и документация on-premise).

## Что готово кратко
- Core: модели с Message.Ciphertext, User.PublicKey, ChatKeyWrap; сервисы под шифротекст; криптослой EndToEndCrypto с WrapKey и UnwrapKey.
- Server: JWT, SQLite, SignalR, Swagger; контракты только под шифротекст; эндпоинты public-key и key-wraps; группы создаются только с полным набором конвертов.
- Console: демо слепого сервера плюс демо групповых конвертов с посторонней Евой.
- Docs: architecture, changelog, defense-notes, setup-new-pc, handoff, ai-start-prompt, team-onboarding.
- Team: доска TASKS.md, замки, ветки, онбординг для ИИ.

## Известные факты и грабли
- messenger.db пересоздаётся удалением при остановленном сервере при любом изменении схемы. Последнее изменение: таблица ChatKeyWraps.
- Создание группы без конверта для каждого участника возвращает 400.
- Эндпоинт key-wraps отдаёт участнику только его собственный конверт.
- Сервер не валидирует формат шифротекстов и конвертов: это работа клиента.
- Коммиты на русском с префиксами feat fix docs chore.
- После каждого шага строка в docs/changelog.md, новые вопросы защиты в docs/defense-notes.md.
- Перед коммитом всегда dotnet build, красную сборку не коммитим.

## Ближайшие шаги
- П6: клиент MAUI: страницы входа, списка чатов, окна переписки; приватный ключ в Keystore или Keychain; шифрование и расшифровка на устройстве; PIN приложения.
- П7: публикация сервера, запуск службой, HTTPS внутри сети, раздел документации on-premise и модель угрозы.
Задачи независимы по файлам, можно раздавать разным людям.

3. Обновить статусы в TASKS.md.
4. Запушить документы последним коммитом сессии.
