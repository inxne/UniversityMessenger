# Передача состояния проекта

Этот файл обновляет ТОТ, КТО ПОСЛЕДНИМ РАБОТАЛ, в конце своей сессии.
Любой участник и любой ИИ начинает сессию с чтения этого файла.

## Текущий этап
П4 завершён. Сервер полностью слепой. Следующие по плану П5 (группы с обернутым ключом), П6 (MAUI клиент) или П7 (документация on-premise).

## Что готово кратко
- Core: модели с Message.Ciphertext и User.PublicKey, сервисы под шифротекст, криптослой EndToEndCrypto.
- Server: JWT, SQLite, SignalR, Swagger. Контракты только под шифротекст: RegisterRequest требует PublicKey, SendCiphertextRequest принимает Ciphertext, UserDto отдаёт PublicKey.
- Эндпоинт GET /api/users/{id}/public-key для раздачи публичных ключей.
- Console: демо слепого сервера.
- Docs: architecture, changelog, defense-notes, setup-new-pc, handoff, ai-start-prompt, team-onboarding.
- Team: доска TASKS.md, замки, ветки, онбординг для ИИ.

## Известные факты и грабли
- messenger.db пересоздаётся удалением при остановленном сервере, если менялась схема.
- Регистрация без публичного ключа возвращает 400.
- Для отправки шифротекста в Swagger/PowerShell передаётся base64-строка в поле ciphertext.
- Сервер не валидирует формат шифротекста: валидация на уровне клиента при расшифровке.
- Коммиты на русском с префиксами feat fix docs chore.
- После каждого шага строка в docs/changelog.md, новые вопросы защиты в docs/defense-notes.md.
- Перед коммитом всегда dotnet build, красную сборку не коммитим.

## Ближайшие шаги
- П5: групповые чаты с обернутым ключом (каждому участнику свой зашифрованный ключ чата).
- П6: клиент .NET MAUI с приватным ключом в защищённом хранилище устройства.
- П7: документация on-premise, модель угрозы, инструкция развёртывания.
Задачи независимы по файлам, можно брать параллельно разным людям.

## Протокол конца сессии
1. Закоммитить и запушить всю работу.
2. Обновить этот файл: этап, что сделано, что дальше, новые грабли.
3. Обновить статусы в TASKS.md.
4. Запушить документы последним коммитом сессии.
